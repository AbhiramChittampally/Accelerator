1.1 DATA FAMILIES & MEASUREMENT TYPES
--------------------------------------------------------------------------------
Every feature in a dataset belongs to one of two primary families:

1. NUMERICAL (Quantitative)
   a) Continuous:
      - Measurements along an unbroken, continuous scale.
      - Can take any real fractional value.
      - Examples: Height (175.5 cm), Weight (68.2 kg), Temperature (98.6 F), Price ($249.99).
      - Typical Treatment: Scaled using StandardScaler or MinMaxScaler.
   b) Discrete:
      - Countable, distinct values (usually non-negative whole integers).
      - Cannot take fractional values between counts.
      - Examples: Number of children (2), Website orders (5), Page views (120).
      - Typical Treatment: Maintained as numeric, or binned into ranges.

2. CATEGORICAL (Qualitative)
   a) Nominal:
      - Discrete groups or categories with NO intrinsic rank or order.
      - Examples: City (NYC, Paris), Eye Color (Blue, Brown), Blood Type (A, B, O), ZIP Code.
      - Typical Treatment: One-Hot Encoding (OHE).
   b) Ordinal:
      - Discrete groups with a CLEAR, meaningful natural ranking or hierarchy.
      - Examples: T-shirt size (S < M < L < XL), Rating (1 < 2 < 3 < 4 < 5 stars),
        Education level (High School < Bachelor < Master < PhD), Customer Satisfaction.
      - Typical Treatment: Ordinal / Integer Encoding.

1.2 SPECIAL DATA TYPES & UNSTRUCTURED DATA
--------------------------------------------------------------------------------
Beyond standard tabular tables, real-world data includes special representations:

- Time Series:
    Meaning: Measurements ordered chronologically by timestamps.
    Examples: Stock prices, ECG heart logs, weather sensor trends.
    Treatment: Lags, rolling window statistics, date decomposition (hour, day, month).

- Text:
    Meaning: Natural human language sequences.
    Examples: Customer reviews, email bodies, support tickets.
    Treatment: Tokenization, CountVectorizer (Bag of Words), TF-IDF, Word Embeddings.

- Image:
    Meaning: Multi-dimensional pixel arrays (Height x Width x Color Channels).
    Examples: Medical X-rays, satellite imagery, photos.
    Treatment: Resize dimensions, normalize pixels (pixel / 255.0), Convolutional Networks.

- Audio:
    Meaning: Continuous sound pressure waveforms recorded over time.
    Examples: Speech recordings, music clips, industrial machine noise.
    Treatment: Fourier Transform, Spectrograms, MFCC feature extraction.

- Video:
    Meaning: Sequences of sequential image frames paired with synchronized audio.
    Examples: Security footage, video action clips.
    Treatment: Frame sampling, 3D Convolutional Neural Networks.

- Graph:
    Meaning: Networks defined by Entities (Nodes/Vertices) and Relationships (Edges).
    Examples: Social networks, fraud transaction rings, molecular chemical bonds.
    Treatment: Adjacency matrices, Graph Neural Networks (GNNs).

1.3 DATA SOURCES & INGESTION PATHWAYS
--------------------------------------------------------------------------------
Data enters machine learning pipelines through several distinct ingestion paths:

1. REST API:
   - Server application endpoints returning JSON or XML.
   - Example: Weather forecasts, financial exchange rates.
   - Best Practice: Implement retry loops with exponential backoff (1s, 2s, 4s).

2. Physical Sensors:
   - Physical measurement devices outputting analog/digital signals.
   - Example: Factory temperature probes, vibration sensors.
   - Best Practice: Edge processing, outlier filtering, analog-to-digital calibration.

3. IoT (Internet of Things):
   - Fleets of connected smart devices transmitting telemetry.
   - Example: Smart home meters, connected vehicle fleets.
   - Best Practice: Message streaming brokers (MQTT, Apache Kafka) -> Stream processing.

4. Web Scraping:
   - Automated scripts parsing structured content from public HTML pages.
   - Example: Competitor price monitoring, job posting aggregators.
   - Best Practice: Periodic scheduled batch scrapers with polite rate limiting.

2.1 MISSING VALUE IMPUTATION & OUTLIER HANDLING
--------------------------------------------------------------------------------
Golden Rule of Data Imputation:
  ALWAYS perform your Train/Test split BEFORE computing imputation statistics!
  1. Calculate the median/mean/mode strictly using the Training set.
  2. Use that exact calculated training value to fill missing gaps in BOTH
     the Training set and the Test set.
  3. Never use the entire dataset to compute imputation values (prevents data leakage).

Recommended Imputation Strategies:
- Numerical features with normal distribution:  Mean
- Numerical features with outliers / skew:      Median (Recommended default)
- Categorical features:                         Mode (Most frequent category)
- Missing target labels:                        Drop rows with missing target

Outlier Detection via IQR (Interquartile Range):
  IQR = Q3 - Q1
  Lower Outlier Fence = Q1 - 1.5 * IQR
  Upper Outlier Fence = Q3 + 1.5 * IQR

  Any data point falling below the Lower Fence or above the Upper Fence is
  flagged as an outlier.
  Handling: Investigate context -> Cap/clip values using .clip() or drop if corrupt.


2.2 FEATURE SCALING: STANDARDIZATION VS. NORMALIZATION VS. ROBUST SCALING
--------------------------------------------------------------------------------

Detailed Breakdown of Scalers:

1. STANDARDIZATION (Z-Score / StandardScaler)
   - Formula:             z = (x - mean) / std
   - Center & Spread:     Transforms data so Mean ≈ 0 and Standard Deviation ≈ 1.
   - Output Range:        Unbounded (typically falls between -3 and +3 for normal data).
   - Fixed Bounds?:       No.
   - Outlier Sensitivity: Moderate (Mean and std are affected by severe outliers).
   - When to Use:         Default choice for most machine learning models.
                          Essential for Linear Regression, Logistic Regression,
                          SVM, k-NN, PCA, and Neural Networks.

2. NORMALIZATION (Min-Max / MinMaxScaler)
   - Formula:             x_norm = (x - min) / (max - min)
   - Center & Spread:     Rescales data to a fixed numerical interval (default 0 to 1).
   - Output Range:        Strictly bounded: [0, 1].
   - Fixed Bounds?:       Yes.
   - Outlier Sensitivity: Very High (A single extreme outlier will compress all
                          normal data points into a tiny sub-range).
   - When to Use:         When bounded inputs are strictly needed (e.g., image
                          pixel values rescaled from 0-255 to 0.0-1.0, or specific
                          neural network activation functions).

3. ROBUST SCALING (RobustScaler)
   - Formula:             x_robust = (x - Q2_median) / (Q3 - Q1_IQR)
   - Center & Spread:     Subtracts the median and divides by the Interquartile Range.
   - Output Range:        Unbounded (centered at median = 0).
   - Fixed Bounds?:       No.
   - Outlier Sensitivity: Very Low (Highly resistant to outliers because it relies
                          on median and IQR rather than mean and variance).
   - When to Use:         When the dataset contains severe, un-trimmed outliers.

Summary Comparison Table:
+---------------------+---------------------------+-------------------------+-------------------------+
| Property            | Standardization (Z-Score) | Normalization (Min-Max) | Robust Scaling          |
+---------------------+---------------------------+-------------------------+-------------------------+
| Calculation         | (x - mean) / std          | (x - min) / (max - min) | (x - median) / IQR      |
| Output Range        | Mean ≈ 0, Std ≈ 1         | Strictly 0 to 1         | Centered at median = 0  |
| Bounded Range?      | No                        | Yes: [0, 1]             | No                      |
| Outlier Sensitivity | Moderate                  | High (Distorts range)   | Highly robust / immune  |
| Primary Use Case    | Default for ML models     | Image pixels / bounded  | Outlier-heavy datasets  |
+---------------------+---------------------------+-------------------------+-------------------------+

Which Algorithms Require Scaling?
- MUST Scale (Distance- or Gradient-Based):
    Linear Regression, Ridge, Lasso, Logistic Regression, Support Vector Machines (SVM),
    k-Nearest Neighbors (k-NN), k-Means Clustering, PCA, Neural Networks.
- DO NOT Need Scaling (Tree-Based Models):
    Decision Trees, Random Forests, Extra Trees, Gradient Boosting, XGBoost,
    LightGBM, CatBoost.
    Why? Decision trees make decisions based on ordering thresholds (e.g., Salary > 50,000).
    A monotonic rescale of features does not alter the split purity.


2.3 CATEGORICAL ENCODING: NOMINAL VS. ORDINAL
--------------------------------------------------------------------------------
1. Nominal Features (One-Hot Encoding):
   - Converts each unique category into a separate binary column (1 or 0).
   - Example: City = [NYC, London, Paris] -> City_NYC, City_London, City_Paris.
   - Dummy Variable Trap: When all categories sum to 1, perfect multicollinearity
     occurs. For linear models, drop one category using drop='first'.

2. Ordinal Features (Ordinal Encoding):
   - Maps ordered categories to ascending integers reflecting their true rank.
   - Example: Education = [High School, Bachelor, Master, PhD] -> [0, 1, 2, 3].

3. ColumnTransformer:
   - Scikit-learn utility to apply different preprocessing pipelines to different
     subsets of columns simultaneously (e.g., StandardScaler on numeric features,
     OneHotEncoder on categoricals) without leaking data.


2.4 FEATURE SELECTION & DIMENSIONALITY CONCEPTS
--------------------------------------------------------------------------------
- Feature Selection: Choosing a subset of the original features without altering them.
- Feature Extraction: Creating new synthetic features by projecting data into lower
  dimensions (e.g., PCA, t-SNE).
- Curse of Dimensionality: As the number of features increases, the volume of feature
  space grows exponentially, data becomes extremely sparse, pairwise Euclidean distances
  become equidistant, and models overfit easily.

Feature Selection Methods:
1. Filter Methods:
   - Evaluates features independently of any machine learning model using statistical scores.
   - Fast and computationally cheap.
   - Examples: SelectKBest using f_regression, f_classif, or mutual_info_classif.
2. Wrapper Methods:
   - Uses an actual machine learning model to evaluate feature subsets iteratively.
   - Example: Recursive Feature Elimination (RFE) removes least important features one by one.
3. Embedded Methods:
   - Feature selection occurs naturally during model training.
   - Examples: Lasso (L1) regression drives non-informative weights to exactly zero;
     Decision Trees measure feature importance by impurity reduction.


2.5 CORE MACHINE LEARNING TERMINOLOGY GLOSSARY
--------------------------------------------------------------------------------
- Dataset:               The complete collection of observations and features.
- Sample (Instance):     A single row or example in the dataset.
- Feature (X):           An input column / predictor variable.
- Target (y):            The ground-truth label / answer we want to predict.
- Dimension:             The total number of feature columns.
- Training Set:          Data used exclusively to optimize model weights/parameters.
- Validation Set:        Data used to tune hyperparameters and choose between models.
- Test Set:              Untouched data used for the final unbiased evaluation.
- Data Leakage:          When information outside the training fold contaminates training.
- Overfitting:           Model memorizes noise in training data; fails to generalize.
- Underfitting:          Model is too simple to capture underlying data relationships.

3. EXPLORATORY DATA ANALYSIS (EDA) & SUMMARY STATISTICS

3.1 MEASURES OF CENTRAL TENDENCY
--------------------------------------------------------------------------------
- Mean (Average):
    Sum of all values divided by total count.
    Formula: x_bar = sum(x_i) / n
    Pros/Cons: Efficient on normally distributed data; highly sensitive to extreme outliers.

- Median (Middle Value):
    The 50th percentile value when data is sorted in ascending order.
    Pros/Cons: Highly robust against outliers; ideal for skewed distributions (e.g., salaries, house prices).

- Mode (Most Frequent Value):
    The value that appears with the highest frequency.
    Pros/Cons: Works with categorical data and discrete counts.

Central Tendency Selection Guide:
+---------------------------------------+-----------------------------+
| Data Characteristic                   | Preferred Starting Measure  |
+---------------------------------------+-----------------------------+
| Symmetric / Normally Distributed      | Mean                        |
| Skewed Data (Long Tails)              | Median                      |
| Severe Outliers Present               | Median                      |
| Categorical / Group Data              | Mode                        |
+---------------------------------------+-----------------------------+


3.2 MEASURES OF SPREAD & CO-MOVEMENT
--------------------------------------------------------------------------------
- Variance (s^2 or sigma^2):
    Average squared deviation of values from their mean.
    Measures overall dispersion; expressed in squared units.

- Standard Deviation (s or sigma):
    Square root of variance: s = sqrt(Variance).
    Measures dispersion in the original measurement units of the data.

- Covariance:
    Measures the joint linear direction of two variables.
    Positive: Both variables increase together.
    Negative: One increases while the other decreases.
    Limitation: Dependent on feature scale; cannot assess strength of relationship.

- Correlation (Pearson r):
    Standardized covariance bounded strictly between -1.0 and +1.0.
    +1.0 = Perfect positive linear relationship.
     0.0 = No linear relationship.
    -1.0 = Perfect negative linear relationship.
    CRITICAL: Correlation does NOT imply causation! Only linear relationships are measured.


3.3 EDA VISUALIZATION GUIDE
--------------------------------------------------------------------------------
- Histogram:
    Shows frequency distribution across numerical bins.
    Best for: Spotting skewness, multimodal peaks, and distribution shape.

- Box Plot:
    Displays 5-number summary (Min, Q1, Median, Q3, Max) plus explicit outlier points.
    Best for: Comparing distributions across groups and spotting outliers.

- Scatter Plot:
    Plots two continuous numerical features against each other.
    Best for: Examining bivariate relationships, clusters, and correlation.

- Heatmap:
    Displays a color-coded matrix of Pearson correlation coefficients.
    Best for: Identifying collinear features and feature-target relationships.

- Pair Plot:
    Grid of scatter plots and histograms for all pairs of numerical variables.
    Best for: Comprehensive multivariate overview of small feature sets.

4. PROBABILITY & BAYES' THEOREM
================================================================================

4.1 PROBABILITY FOUNDATIONS
--------------------------------------------------------------------------------
- Probability Range:
    For any event A: 0 <= P(A) <= 1
    P(Sample Space) = 1

- Complement Rule:
    P(not A) = 1 - P(A)

- Union Rule (OR):
    P(A or B) = P(A) + P(B) - P(A and B)

- Independent Events:
    Event A occurring provides zero information about event B.
    P(A and B) = P(A) * P(B)
    P(A | B) = P(A)

- Conditional Probability:
    Probability of event A occurring given that event B has already occurred.
    P(A | B) = P(A and B) / P(B)      [where P(B) > 0]

- Multiplication Rule:
    P(A and B) = P(A | B) * P(B)


4.2 BAYES' THEOREM
--------------------------------------------------------------------------------
Bayes' Theorem provides the mathematical foundation for updating belief probabilities
based on newly observed evidence:

  Formula:
      P(A | B) = [ P(B | A) * P(A) ] / P(B)

  Conceptual Framework:
      Posterior = (Likelihood * Prior) / Evidence

Terminology:
- Prior P(A):
    Initial baseline probability of hypothesis A before observing evidence.
- Likelihood P(B | A):
    Probability of observing evidence B if hypothesis A is true.
- Evidence P(B):
    Total marginal probability of observing evidence B across all outcomes:
    P(B) = P(B | A)*P(A) + P(B | not A)*P(not A)
- Posterior P(A | B):
    Updated probability of hypothesis A after observing evidence B.

Medical Diagnostic Example:
- Base disease rate (Prior): P(D) = 0.01 (1%)
- Test sensitivity (Likelihood): P(+ | D) = 0.99 (99%)
- False positive rate: P(+ | no D) = 0.01 (1%)
- Probability of positive test (Evidence):
    P(+) = (0.99 * 0.01) + (0.01 * 0.99) = 0.0099 + 0.0099 = 0.0198
- Probability of having disease given positive test (Posterior):
    P(D | +) = (0.99 * 0.01) / 0.0198 = 0.50 (50%)
Even with a 99% accurate test, a positive result only means a 50% true chance of disease!

5. LINEAR ALGEBRA FOUNDATIONS

5.1 SCALARS, VECTORS, MATRICES & TENSORS
--------------------------------------------------------------------------------
- Scalar:  A single number (0D). Example: 5
- Vector:  A 1D array of numbers. Represents a single sample's features. Example: [1, 2, 3]
- Matrix:  A 2D array of numbers (Rows x Columns). Represents an entire dataset. Example: [[1, 2], [3, 4]]
- Tensor:  A generalized array of 3 or more dimensions. Used for images and deep learning.


5.2 VECTOR & MATRIX OPERATIONS
--------------------------------------------------------------------------------
- Vector Addition:
    [1, 2, 3] + [4, 5, 6] = [5, 7, 9]

- Scalar Multiplication:
    3 * [1, 2, 3] = [3, 6, 9]

- Element-wise Multiplication (*):
    [1, 2, 3] * [4, 5, 6] = [4, 10, 18]

- Dot Product (Inner Product):
    Multiplies corresponding elements and sums the result into a scalar:
    a · b = (a1*b1) + (a2*b2) + ... + (an*bn)
    Example: [1, 2, 3] · [4, 5, 6] = 1*4 + 2*5 + 3*6 = 32

- Matrix Multiplication (@):
    Row-by-column dot products.
    Shape Compatibility Rule:
        Matrix A (m x n) @ Matrix B (n x p) = Matrix C (m x p)
        The inner dimensions (n) must match!

- Transpose (A.T):
    Flips a matrix over its diagonal; rows become columns.
    Shape: (m x n) becomes (n x m).


5.3 MACHINE LEARNING CONNECTIONS
--------------------------------------------------------------------------------
- Linear Model Prediction:
    y_hat = w1*x1 + w2*x2 + ... + wd*xd + b
    Expressed cleanly as vector dot product: y_hat = w^T · x + b

- Batch Predictions:
    Predicting for an entire dataset matrix X (m samples x d features):
    y_hat_vector = X @ w + b

- Neural Network Layers:
    Each dense layer applies matrix multiplication and bias addition:
    output = Activation(W @ input + b)

6. CALCULUS & OPTIMIZATION
================================================================================

6.1 DERIVATIVES, GRADIENTS & CHAIN RULE
--------------------------------------------------------------------------------
- Derivative (df/dx):
    Rate of change / instantaneous slope of a function at a specific point.

- Power Rule:
    d/dx (x^n) = n * x^(n - 1)
    Example: d/dx (x^2) = 2x,   d/dx (x^3) = 3x^2

- Partial Derivative (df/dx_i):
    Derivative with respect to one input variable while holding all other variables constant.

- Gradient Vector (grad f):
    Vector containing all first-order partial derivatives:
    grad f = [ df/dx1, df/dx2, ..., df/dxn ]^T
    Property: The gradient vector always points in the direction of STEEPEST ASCENT.
    For minimization, we move in the OPPOSITE direction of the gradient.

- Chain Rule:
    For composite functions y = f(g(x)):
    dy/dx = (dy/dg) * (dg/dx)
    Foundation of the Backpropagation algorithm in neural networks.


6.2 GRADIENT DESCENT ALGORITHM
--------------------------------------------------------------------------------
Gradient Descent is the foundational iterative optimization algorithm used to
find parameter weights that minimize a loss function.

Core Update Equation:
  theta_new = theta_old - (learning_rate * Gradient_of_Loss)

Parameters:
- theta: Model parameters (weights w and bias b).
- learning_rate (eta): Step size.
    Too small: Extremely slow convergence.
    Too large: Overshoots the minimum, oscillates, or diverges.
    Optimal: Smooth, steady convergence to minimum loss.
- Gradient_of_Loss: Slope of loss with respect to parameters.

Variants of Gradient Descent:
1. Batch Gradient Descent:
   - Computes gradient over the entire dataset before making one parameter update.
   - Stable and deterministic, but slow on large datasets.
2. Stochastic Gradient Descent (SGD):
   - Updates parameters after evaluating every single training sample.
   - Very fast and escapes shallow local minima, but trajectory is noisy.
3. Mini-Batch Gradient Descent:
   - Updates parameters after evaluating small batches (e.g., 32, 64, 128 samples).
   - Standard industry compromise balancing vectorization speed and update stability.

Definitions:
- Epoch: One complete pass through the entire training dataset.
- Iteration: A single parameter update step (one mini-batch).

7.1 SUMMARY STATISTICS & OUTLIERS
--------------------------------------------------------------------------------
Sample Mean:
    x_bar = sum(x_i) / n

Population Variance:
    sigma^2 = sum((x_i - mu)^2) / N

Sample Variance (Bessel's correction):
    s^2 = sum((x_i - x_bar)^2) / (n - 1)

Standard Deviation:
    s = sqrt(s^2)

Interquartile Range:
    IQR = Q3 - Q1

Outlier Boundaries:
    Lower Fence = Q1 - 1.5 * IQR
    Upper Fence = Q3 + 1.5 * IQR


7.2 PROBABILITY & BAYES
--------------------------------------------------------------------------------
Basic Probability:
    P(A) = favorable_outcomes / total_outcomes

Complement:
    P(not A) = 1 - P(A)

Conditional Probability:
    P(A | B) = P(A and B) / P(B)

Independent Joint Probability:
    P(A and B) = P(A) * P(B)

Bayes' Theorem:
    P(A | B) = [ P(B | A) * P(A) ] / P(B)


7.3 LINEAR ALGEBRA & CALCULUS
--------------------------------------------------------------------------------
Dot Product:
    a · b = sum(a_i * b_i) = a1*b1 + a2*b2 + ... + an*bn

Matrix Multiplication:
    (m x n) @ (n x p) = (m x p)

Calculus Power Rule:
    d/dx (x^n) = n * x^(n - 1)

Chain Rule:
    dy/dx = (dy/du) * (du/dx)

Gradient Vector:
    grad f = [ df/dx1, df/dx2, ..., df/dxn ]^T


7.4 OPTIMIZATION (GRADIENT DESCENT)
--------------------------------------------------------------------------------
Parameter Update Rule:
    theta_new = theta_old - learning_rate * grad L(theta)

Weight update:
    w_new = w_old - learning_rate * (dL/dw)

Bias update:
    b_new = b_old - learning_rate * (dL/db)

8.1 THE END-TO-END ML PIPELINE
--------------------------------------------------------------------------------
RAW DATA
   ↓
Separate Features (X) and Target (y)
   ↓
TRAIN / TEST SPLIT (Split First!)
   ↓
Data Cleaning & Missing Value Imputation (Fit on Train, Transform on Test)

   ↓

8.2 SUPERVISED LEARNING PARADIGMS
--------------------------------------------------------------------------------
SUPERVISED LEARNING (Ground-truth y is known; model learns mapping X -> y):

1. Regression:
   - Target is a continuous numerical value.
   - Examples: Predicting home sale price, annual salary, quarterly revenue.
   - Core Models: Linear Regression, Ridge, Lasso, Polynomial Regression.

2. Classification:
   - Target is a discrete categorical label.
   - Binary Classification: 2 classes, y in {0, 1} (Spam vs. Not Spam).
   - Multiclass Classification: 3+ classes, y in {1, 2, ..., K} (Cat, Dog, Bird).
   - Core Models: Logistic Regression, Decision Trees, Random Forests, SVM.


8.3 DATASET SPLITTING & CROSS-VALIDATION
--------------------------------------------------------------------------------
- Training Set (~70%):      Used by algorithms to learn weights and decision rules.
- Validation Set (~15%):    Used to compare models and tune hyperparameters.
- Test Set (~15%):          Kept in a vault; evaluated only once at the very end.

- Stratification (stratify=y):
    Preserves original class proportions in every split. Vital for imbalanced targets.

- K-Fold Cross-Validation:
    Splits training data into K equal folds.
    Trains on K-1 folds, validates on the remaining 1 fold; repeats K times and averages scores.

- Stratified K-Fold:
    K-Fold cross-validation that preserves class ratios within every single fold.


8.4 DATA LEAKAGE & CLASS IMBALANCE STRATEGIES
--------------------------------------------------------------------------------
Data Leakage:
  Occurs when information from outside the training set enters model training.
  Yields deceptively high validation scores that collapse in production.
  Common forms:
  - Preprocessing Leakage: Fitting scalers or imputers on the full dataset before splitting.
  - Target Leakage: Including features that will not be available at prediction time.
  - Prevention: Always split first; encapsulate steps in Scikit-Learn Pipeline objects.

Class Imbalance:
  Occurs when one class heavily outnumbers another (e.g., 99% legitimate, 1% fraud).
  Accuracy is a useless metric for imbalanced data (predicting all 0s gives 99% accuracy).
  Remedies:
  - Random Oversampling: Duplicates minority class samples.
  - Random Undersampling: Discards majority class samples.
  - SMOTE (Synthetic Minority Over-sampling Technique): Creates synthetic minority
    samples along line segments connecting k-nearest minority neighbors.
  - Class Weights (class_weight='balanced'): Penalizes errors on minority samples
    inversely proportional to class frequency.
  - Golden Rule: Apply SMOTE/resampling ONLY on training data, NEVER on test data!

9. SUPERVISED LEARNING: REGRESSION
================================================================================

9.1 LINEAR & POLYNOMIAL REGRESSION
--------------------------------------------------------------------------------
- Simple Linear Regression:
    y = w*x + b
- Multiple Linear Regression:
    y = w1*x1 + w2*x2 + ... + wd*xd + b
- Ordinary Least Squares (OLS):
    Finds weights that mathematically minimize the sum of squared residuals (RSS).
- Polynomial Regression:
    Expands feature space by creating non-linear combinations (x^2, x^3, x1*x2).
    Allows linear models to fit curved non-linear patterns.
    Warning: High degrees cause severe overfitting.


9.2 REGULARIZATION: RIDGE, LASSO & ELASTIC NET
--------------------------------------------------------------------------------
Regularization adds a penalty to the loss function to shrink weights and stop overfitting:

1. RIDGE REGRESSION (L2 Regularization):
   - Loss = MSE + alpha * sum(w_j^2)
   - Shrinks weight magnitudes smoothly toward zero.
   - Handles multicollinearity well. Weights never become exactly zero.

2. LASSO REGRESSION (L1 Regularization):
   - Loss = MSE + alpha * sum(|w_j|)
   - Drives uninformative weights strictly to zero.
   - Performs automatic feature selection.

3. ELASTIC NET (L1 + L2):
   - Loss = MSE + alpha * [ r * sum(|w_j|) + ((1-r)/2) * sum(w_j^2) ]
   - Balances Ridge and Lasso; effective when multiple features are correlated.


9.3 REGRESSION EVALUATION METRICS
--------------------------------------------------------------------------------
- Mean Absolute Error (MAE):
    MAE = (1/n) * sum( |y_i - y_hat_i| )
    Average magnitude of error in original units. Robust to outliers.

- Mean Squared Error (MSE):
    MSE = (1/n) * sum( (y_i - y_hat_i)^2 )
    Heavily penalizes large errors. Expressed in squared units.

- Root Mean Squared Error (RMSE):
    RMSE = sqrt(MSE)
    Standard metric. Same units as target. Sensitive to outliers.

- R-Squared (Coefficient of Determination):
    R^2 = 1 - (SS_residual / SS_total)
    Proportion of target variance explained by model compared to mean baseline.
    R^2 = 1.0 means perfect prediction; R^2 = 0.0 means no better than predicting mean.

- Adjusted R-Squared:
    Adjusted R^2 = 1 - [ (1 - R^2)*(n - 1) / (n - d - 1) ]
    Penalizes adding useless features to regression models.

10. SUPERVISED LEARNING: CLASSIFICATION
================================================================================

10.1 REGRESSION VS. CLASSIFICATION
--------------------------------------------------------------------------------
+------------------+------------------------------+------------------------------+
| Property         | Regression                   | Classification               |
+------------------+------------------------------+------------------------------+
| Target Output    | Continuous numerical number  | Discrete category / class    |
| Example          | House Price ($450,000)       | Email (Spam vs. Not Spam)    |
| Core Algorithms  | Linear, Ridge, Lasso         | Logistic, Trees, SVM, k-NN   |
| Evaluation       | MAE, MSE, RMSE, R^2          | Accuracy, Precision, Recall, |
|                  |                              | F1-Score, ROC-AUC            |
+------------------+------------------------------+------------------------------+


10.2 LOGISTIC REGRESSION & DECISION BOUNDARIES
--------------------------------------------------------------------------------
Logistic Regression models the probability of binary class membership:

1. Linear Combination (Logit):
   z = w^T · x + b

2. Sigmoid Function:
   P(y = 1 | x) = sigma(z) = 1 / (1 + e^(-z))
   Maps any input z (-inf to +inf) into a valid probability between 0.0 and 1.0.

3. Decision Boundary:
   Set at probability threshold = 0.5 (where z = 0):
   w^T · x + b = 0

4. Loss Function (Binary Cross-Entropy / Log Loss):
   LogLoss = -(1/n) * sum[ y*log(p) + (1 - y)*log(1 - p) ]
   Heavily penalizes confident wrong predictions.


10.3 CLASSICAL CLASSIFICATION ALGORITHMS
--------------------------------------------------------------------------------
- k-Nearest Neighbors (k-NN):
    Classifies a point by majority vote of its k closest neighbors.
    Distance-based: Feature scaling is MANDATORY.

- Decision Trees:
    Splits data using hierarchical if/else questions to minimize Gini Impurity or Entropy.
    Non-linear, interpretable, does not require scaling, but overfits easily without depth limits.

- Random Forest:
    Ensemble of decision trees trained on bootstrap samples with random feature subsets.
    Aggregates predictions via majority voting. Highly robust against overfitting.

- Support Vector Machines (SVM):
    Finds the optimal hyperplane that maximizes the separation margin between classes.
    Uses support vectors; parameter C controls margin violation penalties.
    Kernel trick (RBF, Polynomial) projects non-linear data into higher dimensions.

- Naive Bayes:
    Probabilistic classifier using Bayes' Theorem with feature independence assumptions.
    Extremely fast; excellent baseline for text classification.


10.4 CLASSIFICATION EVALUATION METRICS & CONFUSION MATRIX
--------------------------------------------------------------------------------
The Confusion Matrix:
                 PREDICTED
                 Class 0          Class 1
ACTUAL   Class 0   True Negative    False Positive (Type I Error)
CLASS              (TN)             (FP)
         Class 1   False Negative   True Positive
                   (FN - Type II)   (TP)

Formulas:
- Accuracy:
    (TP + TN) / (TP + TN + FP + FN)
    Caution: Deceptive on imbalanced data.

- Precision:
    TP / (TP + FP)
    Out of all predicted positives, how many were correct? Focus: Minimize False Positives (e.g., spam).

- Recall (Sensitivity / True Positive Rate - TPR):
    TP / (TP + FN)
    Out of all actual positives, how many did we catch? Focus: Minimize False Negatives (e.g., cancer).

- Specificity (True Negative Rate - TNR):
    TN / (TN + FP)

- False Positive Rate (FPR):
    FP / (FP + TN) = 1 - Specificity

- F1-Score:
    Harmonic mean of Precision and Recall:
    F1 = 2 * (Precision * Recall) / (Precision + Recall)


10.5 ROC & PRECISION-RECALL CURVES
--------------------------------------------------------------------------------
- ROC Curve:
    Plots True Positive Rate (Recall) vs. False Positive Rate across all thresholds (0.0 to 1.0).
    ROC-AUC Score: Area under the ROC curve.
    1.0 = Perfect classifier; 0.5 = Random guessing.

- Precision-Recall (PR) Curve:
    Plots Precision vs. Recall across thresholds.
    Recommended over ROC-AUC when evaluating severely imbalanced datasets.

11. PIPELINES, HYPERPARAMETER TUNING & EARLY STOPPING
================================================================================

11.1 HYPERPARAMETER TUNING: GRID SEARCH VS. RANDOM SEARCH
--------------------------------------------------------------------------------
- Parameter:       Learned automatically during training (e.g., weights w, biases b).
- Hyperparameter:  Set manually before training (e.g., learning rate, max_depth, C, n_estimators).

Comparison:
- GridSearchCV:
    Evaluates every exhaustive combination of specified values.
    Pros: Thorough.
    Cons: Extremely slow on large parameter grids.

- RandomizedSearchCV:
    Samples a fixed number (n_iter) of random combinations from distributions.
    Pros: Fast, efficient, and finds near-optimal parameters in a fraction of the time.

Tuning Workflow:
  Data -> Train/Test Split -> Cross-Validation on Train -> Try Hyperparameters ->
  Select Best Model -> Evaluate Once on Untouched Test Set.


11.2 EARLY STOPPING MECHANISM
--------------------------------------------------------------------------------
Monitors validation performance during iterative model training (e.g., neural nets, gradient boosting):
- Halts training when validation loss stops improving.
- Prevents unnecessary computation and stops overfitting before it starts.
- Parameters:
    early_stopping=True
    validation_fraction: Portion reserved for validation tracking (e.g., 0.10)
    n_iter_no_change (Patience): Number of epochs with no improvement before halting
    tol: Minimum change required to qualify as improvement

12. UNSUPERVISED LEARNING: CLUSTERING
================================================================================

12.1 OVERVIEW OF UNSUPERVISED LEARNING
--------------------------------------------------------------------------------
Unsupervised learning operates on unlabeled data (input X only, no target y):
1. Clustering: Discover natural groupings of similar points.
2. Dimensionality Reduction: Compress and visualize high-dimensional data.
3. Anomaly Detection: Identify abnormal or outlier points.
4. Association Rule Mining: Discover item co-occurrence rules.


12.2 CLUSTERING EVALUATION METRICS
--------------------------------------------------------------------------------
Since no ground-truth labels exist, clusters are evaluated via intrinsic geometry:

- Inertia (Within-Cluster Sum of Squares - WCSS):
    Sum of squared distances from samples to their assigned cluster centroid.
    Lower is better (for a fixed K).

- Elbow Method:
    Plotting Inertia vs. K to identify the diminishing-returns "elbow" bend.

- Silhouette Score:
    Measures how close a sample is to its own cluster compared to neighboring clusters.
    Range: -1.0 to +1.0. Higher is better (> 0.5 indicates strong structure).

- Davies-Bouldin Index (DBI):
    Ratio of within-cluster scatter to between-cluster separation. Lower is better.

- Calinski-Harabasz Index (CH):
    Ratio of between-cluster dispersion to within-cluster dispersion. Higher is better.


12.3 K-MEANS CLUSTERING
--------------------------------------------------------------------------------
K-Means partitions data into K non-overlapping clusters:
1. Specify K.
2. Initialize K random centroids.
3. Assign each sample to its nearest centroid (Euclidean distance).
4. Recalculate centroids as the mean position of assigned samples.
5. Repeat steps 3-4 until centroids stop moving (convergence).

Characteristics & Limitations:
- Must specify K beforehand.
- Feature scaling (StandardScaler) is mandatory.
- Assumes spherical, equal-variance clusters; struggles with irregular shapes.
- Sensitive to outliers.


12.4 HIERARCHICAL CLUSTERING (AGGLOMERATIVE)
--------------------------------------------------------------------------------
Bottom-up clustering approach:
1. Every observation starts as its own individual cluster.
2. The two closest clusters are merged iteratively.
3. Continues until all points merge into a single master cluster.

Linkage Criteria:
- Single Linkage:   Minimum distance between any point in Cluster A and Cluster B.
                    Can create long chain clusters.
- Complete Linkage: Maximum distance between point pairs. Produces compact clusters.
- Average Linkage:  Average distance between all point pairs.
- Ward Linkage:     Minimizes the increase in total within-cluster variance.
                    Produces equal-sized, spherical clusters (Recommended default).

Dendrogram:
  Tree diagram showing the complete merge history.
  The vertical height of a merge represents distance.
  Slicing horizontally across the dendrogram yields a specific number of clusters.


12.5 DENSITY-BASED CLUSTERING: DBSCAN & OPTICS
--------------------------------------------------------------------------------
DBSCAN (Density-Based Spatial Clustering of Applications with Noise):
- Discovers clusters of arbitrary shape and explicitly detects noise points.
- Parameters:
    eps: Neighborhood search radius.
    min_samples: Minimum points required within eps radius to form a dense core.
- Point Types:
    Core Point: Has at least min_samples points within eps.
    Border Point: Within eps of a core point, but has fewer than min_samples.
    Noise Point: Neither core nor border. Labeled as -1.
- Advantages: No need to specify K; discovers non-spherical shapes; handles noise.
- Limitation: Struggles with datasets having widely varying density levels.

OPTICS:
- Extends DBSCAN to handle multi-scale variable densities.
- Constructs an ordered reachability plot to extract clusters at multiple density thresholds.


12.6 PROBABILISTIC CLUSTERING: GAUSSIAN MIXTURE MODELS (GMM)
--------------------------------------------------------------------------------
Assumes data is generated from a mixture of K Gaussian probability distributions:
- Soft Clustering: Computes probabilities of cluster membership via predict_proba().
- Trained using the Expectation-Maximization (EM) algorithm:
    E-step: Estimates responsibility probabilities for each sample.
    M-step: Updates Gaussian parameters (mean, covariance, mixture weight).
- Covariance Types:
    full:      Each component has its own flexible covariance (elliptical).
    tied:      All components share the same covariance.
    diag:      Diagonal covariance (axis-aligned ellipses).
    spherical: Single variance per component (spherical).
- Model Selection: Choose component count K with the lowest Bayesian Information Criterion (BIC).


12.7 SUBCLUSTER & DENSITY MODE SEEKING: BIRCH & MEAN SHIFT
--------------------------------------------------------------------------------
- BIRCH (Balanced Iterative Reducing and Clustering using Hierarchies):
    Builds a Clustering Feature Tree (CF Tree) to compress massive datasets into
    compact subclusters. Extremely fast on large datasets.

- Mean Shift:
    Non-parametric algorithm that shifts points toward local density modes.
    Automatically determines the number of clusters without specifying K.


12.8 COMPREHENSIVE CLUSTERING COMPARISON
--------------------------------------------------------------------------------
+--------------+-----------------------+-------------+---------------+-----------------------+
| Algorithm    | Core Philosophy       | Specify K?  | Noise Label?  | Cluster Geometry      |
+--------------+-----------------------+-------------+---------------+-----------------------+
| K-Means      | Centroids & variance  | Yes         | No            | Spherical / Compact   |
| Hierarchical | Merge tree hierarchy  | Cut later   | No            | Linkage-dependent     |
| DBSCAN       | Density-connectivity  | No          | Yes (-1)      | Arbitrary shapes      |
| OPTICS       | Multi-scale density   | No          | Yes (-1)      | Arbitrary shapes      |
| GMM          | Gaussian distribution | Yes         | Probabilities | Elliptical / Gaussian |
| BIRCH        | CF Tree compression   | Optional    | No            | Spherical subclusters |
| Mean Shift   | Density mode seeking  | No          | No            | Dense clusters        |
+--------------+-----------------------+-------------+---------------+-----------------------+

13. UNSUPERVISED LEARNING: DIMENSIONALITY REDUCTION
================================================================================

13.1 PRINCIPAL COMPONENT ANALYSIS (PCA)
--------------------------------------------------------------------------------
PCA is an unsupervised linear transformation technique that projects data onto
orthogonal axes that maximize variance:

Step-by-Step Mechanism:
1. Center the data by subtracting feature means.
2. Compute the feature covariance matrix.
3. Calculate Eigenvalues and Eigenvectors:
   - Eigenvectors define the directions of the principal components.
   - Eigenvalues quantify the amount of variance explained along each component.
4. Sort eigenvectors in descending order of their eigenvalues.
5. Project original data onto the top K eigenvectors.

Key Properties:
- PC1 captures the maximum possible variance.
- PC2 is orthogonal (uncorrelated) to PC1 and captures the next highest variance.
- explained_variance_ratio_ shows percentage of total variance retained per PC.
- Cumulative variance: Often tuned to retain 95% of information (n_components=0.95).
- Always scale features (StandardScaler) before running PCA!


13.2 COMPARISON OF DIMENSIONALITY REDUCTION METHODS
--------------------------------------------------------------------------------
1. PCA:
   Linear, unsupervised. Maximizes variance. Standard choice for general compression.

2. Truncated SVD:
   Linear, unsupervised. Works directly on sparse matrices without mean centering.
   Ideal for text TF-IDF matrices (Latent Semantic Analysis - LSA).

3. Linear Discriminant Analysis (LDA):
   Linear, SUPERVISED. Uses class labels to maximize between-class separation.
   Maximum number of components is (number of classes - 1).

4. t-SNE (t-Distributed Stochastic Neighbor Embedding):
   Non-linear, unsupervised. Preserves local neighborhood distances.
   Best for 2D/3D visualization of complex clusters. Cannot transform new data.

5. UMAP (Uniform Manifold Approximation and Projection):
   Non-linear, unsupervised. Preserves both local and global structure.
   Much faster than t-SNE and supports transforming new unseen data points.

14. UNSUPERVISED LEARNING: ASSOCIATION RULE MINING
================================================================================

14.1 CORE METRICS: SUPPORT, CONFIDENCE & LIFT
--------------------------------------------------------------------------------
Association rules discover relationships of the form: If Item A, then Item B (A -> B).

1. Support:
   Proportion of transactions containing both items A and B.
   Support(A -> B) = count(A and B) / total_transactions

2. Confidence:
   Probability that a transaction contains item B given that it already contains A.
   Confidence(A -> B) = Support(A and B) / Support(A)

3. Lift:
   Measures how much more often items A and B occur together than expected by chance.
   Lift(A -> B) = Support(A and B) / [ Support(A) * Support(B) ]
                = Confidence(A -> B) / Support(B)

Lift Interpretation:
- Lift > 1.0:  Positive association (Items occur together more often than chance).
- Lift = 1.0:  Independence (Occurrence of A has no effect on occurrence of B).
- Lift < 1.0:  Negative association (Items substitute or repel each other).


14.2 APRIORI VS. FP-GROWTH
--------------------------------------------------------------------------------
- Apriori Algorithm:
    Relies on the Downward Closure Property: Any subset of a frequent itemset
    must also be frequent. Generates candidate itemsets level by level.
    Requires multiple full database passes; slow on large transaction sets.

- FP-Growth (Frequent Pattern Growth):
    Constructs a compact tree structure called an FP-Tree.
    Extracts frequent patterns directly by pattern growth without candidate generation.
    Requires only 2 database passes; dramatically faster on large datasets.

15. UNSUPERVISED LEARNING: TOPIC MODELING
================================================================================

15.1 LDA VS. NMF
--------------------------------------------------------------------------------
Topic modeling discovers abstract thematic topics across text document collections:

1. Latent Dirichlet Allocation (LDA):
   - Probabilistic Bayesian generative model.
   - Input: Raw word count matrix (from CountVectorizer).
   - Assumption: Documents are mixtures of topics; topics are mixtures of words.
   - Uses Dirichlet prior distributions and Gibbs Sampling / Variational Inference.

2. Non-Negative Matrix Factorization (NMF):
   - Linear algebra matrix decomposition technique: V ≈ W @ H
     V: Original document-term matrix (from TfidfVectorizer)
     W: Document-to-topic weight matrix (Documents x Topics)
     H: Topic-to-word weight matrix (Topics x Words)
   - Constraint: All matrix entries in W and H must be non-negative (>= 0).
   - Produces clean, additive parts-based topic representations.

16. BIAS-VARIANCE DECOMPOSITION & LEARNING CURVES
================================================================================

16.1 THEORETICAL ERROR DECOMPOSITION: BIAS, VARIANCE & NOISE
--------------------------------------------------------------------------------
The fundamental goal of supervised machine learning is to build a model that
generalizes well to unseen test data. The expected test error of any supervised
learning algorithm can be mathematically decomposed into three distinct components:

    Total Expected Test Error = Bias^2 + Variance + Irreducible Error (Noise)

1. BIAS (Underfitting Error):
   - Definition: The difference between the average prediction of our model and
     the true target value we are trying to predict.
   - Root Cause: Oversimplified assumptions in the model architecture (e.g.,
     fitting a straight line to quadratic data).
   - Characteristic: The model fails to capture underlying patterns in the
     training data, producing high error on BOTH training and testing datasets.

2. VARIANCE (Overfitting Error):
   - Definition: The variability of model predictions for a given data point
     if the model were trained on different random subsets of the training data.
   - Root Cause: Excessive model complexity and sensitivity to random fluctuations
     or noise in the specific training sample.
   - Characteristic: The model memorizes training noise, achieving near-zero error
     on the training set but failing drastically on unseen validation data.

3. IRREDUCIBLE ERROR (Noise - sigma^2):
   - Definition: The inherent randomness or unobserved confounding factors in the
     true data-generating process.
   - Property: No algorithm, regardless of complexity or data volume, can eliminate
     irreducible noise. It sets the theoretical lower bound (Bayes Error Rate)
     for model performance.

THE TRADEOFF DYNAMICS:
- As model complexity INCREASES:
    * Bias DECREASES (model can fit intricate patterns).
    * Variance INCREASES (model becomes sensitive to sample idiosyncrasies).
- Optimal Model Complexity:
    * Occurs at the sweet spot where the sum of (Bias^2 + Variance) is MINIMIZED.


16.2 UNDERFITTING VS. OVERFITTING DIAGNOSTIC INDICATORS
--------------------------------------------------------------------------------
+-------------------+-----------------------------+-----------------------------+
| Diagnostic Metric | High Bias (Underfitting)    | High Variance (Overfitting) |
+-------------------+-----------------------------+-----------------------------+
| Training Error    | HIGH (Poor performance)     | LOW (Near perfect / zero)   |
| Validation Error  | HIGH (Poor performance)     | HIGH (Significant drop)     |
| Train-Val Gap     | VERY SMALL (Both are poor)  | LARGE (Generalization gap)  |
| Model Complexity  | Too Simple (Under-param)    | Too Complex (Over-param)    |
| Root Problem      | Inability to capture signal | Memorizing sample noise     |
+-------------------+-----------------------------+-----------------------------+


16.3 DIAGNOSING MODELS VIA LEARNING CURVES
--------------------------------------------------------------------------------
A Learning Curve plots training performance (score or loss) and cross-validation
performance as a function of the training dataset size (N samples).

1. HIGH BIAS (UNDERFITTING) LEARNING CURVE PATTERN:
   - Behavior:
       * Training error increases quickly and plateaus at an unacceptably high error.
       * Validation error decreases slightly but plateaus very close to the training error.
       * Both curves converge with a small gap, but at a SUB-PAR performance level.
   - Critical Takeaway:
       * Adding more training instances will NOT improve the model!
       * The limitation is model capacity, not sample size.

   Visual ASCII Representation:
   High Error |
              |    Validation Loss (Plateaus High)
              |  ----------------------------------
              |    Training Loss (Plateaus High)
              |  ----------------------------------
    Low Error |_____________________________________
                 Few Samples            Many Samples

2. HIGH VARIANCE (OVERFITTING) LEARNING CURVE PATTERN:
   - Behavior:
       * Training error remains very low across all sample sizes.
       * Validation error starts very high and steadily slopes downward as N increases.
       * A substantial GAP remains between the training and validation curves.
   - Critical Takeaway:
       * Adding more training instances WILL help close the gap and improve generalization!
       * Regularization and feature pruning are also immediately effective.

   Visual ASCII Representation:
   High Error |
              |  \  Validation Loss (Slowly decreasing)
              |   \---------------------------------
              |     [ Generalization Gap ]
              |   ----------------------------------
    Low Error |  Training Loss (Stays very low)
              |_____________________________________
                 Few Samples            Many Samples


16.4 PRACTICAL ACTION PRESCRIPTIONS (HIGH BIAS VS. HIGH VARIANCE FIXES)
--------------------------------------------------------------------------------
IF YOUR MODEL HAS HIGH BIAS (UNDERFITTING):
  [+] Increase model complexity (e.g., deeper trees, higher polynomial degree,
      non-linear kernels in SVM, larger neural network architecture).
  [+] Engineer new informative features, interaction terms, or domain ratios.
  [+] Decrease regularization penalties (reduce alpha/lambda in Ridge/Lasso,
      increase C in Logistic Regression / SVM).
  [+] Decrease early stopping patience or train for more epochs/iterations.
  [-] DO NOT waste resources collecting more of the same data features.

IF YOUR MODEL HAS HIGH VARIANCE (OVERFITTING):
  [+] Collect and annotate more training samples (expands empirical coverage).
  [+] Reduce feature space: apply feature selection, L1 regularization, or PCA.
  [+] Constrain model complexity (limit tree max_depth, increase min_samples_leaf,
      reduce polynomial degree).
  [+] Increase regularization strength (increase alpha/lambda, apply dropout).
  [+] Use ensemble bagging methods (e.g., Random Forest averages independent trees,
      directly reducing variance without increasing bias).

17. ADVANCED ENSEMBLE LEARNING: BOOSTING, STACKING & VOTING
================================================================================

17.1 ENSEMBLE PHILOSOPHY: BAGGING VS. BOOSTING VS. STACKING
--------------------------------------------------------------------------------
Ensemble learning combines predictions from multiple individual models (base learners)
to build an aggregated predictor that outperforms any individual component.

The three primary ensemble paradigms operate on distinct statistical mechanisms:

1. BAGGING (Bootstrap Aggregating):
   - Training: Independent base learners trained in PARALLEL on random bootstrap
     subsets of the training data (sampling with replacement).
   - Combination: Simple majority vote (classification) or mean average (regression).
   - Primary Purpose: Drastically REDUCES VARIANCE without increasing bias.
   - Canonical Example: Random Forest (aggregates unpruned, high-variance decision trees).

2. BOOSTING:
   - Training: Base learners trained SEQUENTIALLY. Each subsequent learner is explicitly
     trained to correct the residual errors made by the previous learners.
   - Combination: Weighted vote or weighted sum of all weak learners.
   - Primary Purpose: Drastically REDUCES BIAS (and secondarily variance).
   - Canonical Examples: AdaBoost, Gradient Boosting (GBM), XGBoost, LightGBM, CatBoost.

3. STACKING (Stacked Generalization):
   - Training: Diverse, heterogeneous base models (e.g., Random Forest + XGBoost + SVM)
     trained on the dataset.
   - Combination: Out-of-fold predictions from base models are used as features to train
     a secondary META-LEARNER (e.g., Logistic Regression or Ridge).
   - Primary Purpose: Blends complementary algorithmic inductive biases.


17.2 ADABOOST (ADAPTIVE BOOSTING): SAMPLE REWEIGHTING & STUMP AGGREGATION
--------------------------------------------------------------------------------
Introduced by Freund and Schapire (1995). AdaBoost converts a collection of weak
learners (typically "decision stumps" - decision trees with depth = 1) into a strong learner.

MATHEMATICAL STEP-BY-STEP WORKFLOW:
1. Initialize Sample Weights:
   Every training sample receives an equal initial weight:
       w_i^(1) = 1 / N,   for i = 1, 2, ..., N

2. For iteration m = 1 to M:
   a. Fit weak classifier h_m(x) to the training data using weights w_i^(m).
   b. Calculate the weighted classification error:
          error_m = sum(w_i^(m) * I(y_i != h_m(x_i))) / sum(w_i^(m))
   c. Calculate learner stage weight (alpha_m):
          alpha_m = 0.5 * ln( (1 - error_m) / error_m )
          * If error_m < 0.5: alpha_m > 0 (learner is accurate, gets positive vote).
          * As error_m -> 0: alpha_m -> +infinity (decisive influence).
   d. Update sample weights for the next iteration:
          w_i^(m+1) = w_i^(m) * exp(-alpha_m * y_i * h_m(x_i))
          * Misclassified samples receive increased weights (exp(+alpha_m)).
          * Correctly classified samples receive decreased weights (exp(-alpha_m)).
   e. Renormalize weights so sum(w_i^(m+1)) = 1.

3. Final Aggregated Output:
   The ensemble makes predictions via sign-weighted majority voting:
       H(x) = sign( sum_{m=1}^{M} alpha_m * h_m(x) )


17.3 GRADIENT BOOSTING MACHINES (GBM): LOSS GRADIENTS & PSEUDO-RESIDUALS
--------------------------------------------------------------------------------
Introduced by Jerome Friedman (2001). GBM reformulates boosting as an iterative
gradient descent optimization in FUNCTION SPACE rather than parameter space.

KEY CONCEPT: PSEUDO-RESIDUALS
Instead of reweighting samples (like AdaBoost), Gradient Boosting trains each new
tree to predict the negative gradient of the loss function with respect to the
current model's predictions.

1. Objective: Minimize total empirical loss:
       L_total = sum_{i=1}^{N} L(y_i, F(x_i))

2. The Pseudo-Residual for instance i at iteration m is defined as:
       r_{im} = - [ d L(y_i, F(x_i)) / d F(x_i) ] evaluated at F(x) = F_{m-1}(x)

   * For Squared Error Loss (L = 0.5 * (y - F)^2):
         r_{im} = y_i - F_{m-1}(x_i)  --> Exact arithmetic residuals!
   * For Binary Log-Loss (L = -[y*ln(p) + (1-y)*ln(1-p)]):
         r_{im} = y_i - p_i          --> Residual in predicted probability space!

3. Shrinkage (Learning Rate eta):
   To prevent overfitting, each tree's contribution is scaled by shrinkage parameter eta (0 < eta <= 1):
       F_m(x) = F_{m-1}(x) + eta * gamma_m * h_m(x)
   Using a smaller learning rate (e.g., eta = 0.01 - 0.1) paired with a larger number of trees
   consistently yields superior generalization.


17.4 XGBOOST: EXACT GREEDY ALGORITHM, REGULARIZATION & 2ND ORDER TAYLOR APPROXIMATION
--------------------------------------------------------------------------------
XGBoost (eXtreme Gradient Boosting, Chen & Guestrin 2016) is a highly scalable,
computationally optimized implementation of gradient boosting that dominates tabular ML.

KEY INNOVATIONS OVER STANDARD GBM:

1. Second-Order Taylor Expansion of the Objective Function:
   Standard GBM uses only first-order gradients. XGBoost expands the loss using both
   first and second derivatives (gradient and Hessian):
       L_obj^(t) ≈ sum_{i=1}^{N} [ L(y_i, y_hat_i^(t-1)) + g_i * f_t(x_i) + 0.5 * h_i * f_t(x_i)^2 ] + Omega(f_t)

   Where:
       First derivative (Gradient):  g_i = d L(y_i, y_hat_i^(t-1)) / d y_hat_i^(t-1)
       Second derivative (Hessian):  h_i = d^2 L(y_i, y_hat_i^(t-1)) / d (y_hat_i^(t-1))^2

2. Explicit Tree Complexity Regularization (Omega):
       Omega(f_t) = gamma * T + 0.5 * lambda * sum_{j=1}^{T} w_j^2

   Where:
       T      = Total number of terminal leaf nodes in the tree.
       w_j    = Continuous weight/score assigned to leaf j.
       gamma  = Minimum loss reduction required to make a further partition (pruning penalty).
       lambda = L2 regularization penalty on leaf weights (prevents extreme weights).

3. Optimal Leaf Weight Formula:
   By taking the derivative of the regularized objective with respect to leaf weight w_j,
   the closed-form optimal weight for leaf j is:
       w_j* = - ( sum_{i in I_j} g_i ) / ( sum_{i in I_j} h_i + lambda )
            = - G_j / (H_j + lambda)

4. Gain Metric for Split Finding:
   XGBoost determines the best split at any node by calculating the gain:
       Gain = 0.5 * [ (G_L^2 / (H_L + lambda)) + (G_R^2 / (H_R + lambda)) - ((G_L + G_R)^2 / (H_L + H_R + lambda)) ] - gamma
   If Gain <= 0, the node is not split (automatic early tree pruning).

5. Sparsity-Aware Split Finding:
   XGBoost automatically learns an optimal default routing direction for missing values
   during split evaluation, eliminating the requirement for manual missing value imputation.


17.5 LIGHTGBM: LEAF-WISE GROWTH, GOSS & EFB
--------------------------------------------------------------------------------
Developed by Microsoft Research (2017), LightGBM was designed for massive tabular datasets
where training standard GBM or XGBoost is computationally prohibitive.

CORE ARCHITECTURAL PILLARS:

1. Leaf-Wise (Best-First) Tree Growth vs. Level-Wise (Depth-First):
   - Traditional GBM/XGBoost grows trees level-by-level, splitting all leaves at depth d
     before moving to depth d+1.
   - LightGBM grows trees LEAF-WISE: at each step, it splits only the single leaf that produces
     the maximum loss reduction (highest gain), regardless of level.
   - Benefit: Achieves much lower loss for the same total number of leaves.
   - Overfitting Protection: Controlled by `max_depth` and `min_data_in_leaf`.

   Visual Comparison:
   Level-Wise (XGBoost Default):        Leaf-Wise (LightGBM):
            (Root)                               (Root)
           /      \                             /      \
        (Node)  (Node)                       (Node)   (Split)  <-- Highest Gain
       /    \   /    \                                /     \
     (L)   (L) (L)   (L)                            (Node)  (Split)

2. Gradient-based One-Side Sampling (GOSS):
   - Concept: Instances with small gradients are already well-trained; instances with
     large gradients contribute significantly more to information gain.
   - Mechanism: GOSS retains 100% of instances with top gradients (fraction a, e.g., 20%),
     and randomly samples a small fraction of small-gradient instances (fraction b, e.g., 10%).
   - Correction: Small-gradient instances are multiplied by a weight factor (1 - a) / b
     when calculating information gain to maintain an unbiased data distribution.

3. Exclusive Feature Bundling (EFB):
   - Concept: High-dimensional tabular datasets are often sparse; many features are mutually
     exclusive (they never take non-zero values simultaneously, e.g., one-hot vectors).
   - Mechanism: EFB bundles mutually exclusive features into a single composite feature,
     slashing feature scan time from O(features) to O(bundles) with zero information loss.

4. Histogram-Based Splitting:
   - Buckets continuous feature values into discrete integer bins (typically 256 bins).
   - Reduces memory consumption by up to 80% and accelerates split finding dramatically.


17.6 CATBOOST: SYMMETRIC OBLIVIOUS TREES, ORDERED BOOSTING & CATEGORICAL HANDLING
--------------------------------------------------------------------------------
Developed by Yandex (2017), CatBoost excels right out of the box with default parameters,
especially on datasets rich with high-cardinality categorical variables.

CORE ARCHITECTURAL PILLARS:

1. Symmetric / Oblivious Decision Trees:
   - All nodes at the exact same depth share the identical split condition across the entire level.
   - Benefits:
       * Acts as a structural regularizer preventing overfitting.
       * Enables blazingly fast inference: prediction is evaluated via simple binary bitwise masks,
         executing up to 10x faster than asymmetric trees on production CPUs.

2. Ordered Boosting (Combating Target Leakage in Training):
   - Standard GBDT calculates gradients on the same training set, causing prediction shift / bias.
   - CatBoost uses Ordered Boosting: for each sample, it computes gradients using a model trained
     strictly on samples preceding it in a randomized virtual sequence.

3. Native Categorical Feature Processing:
   - Encodes categorical features dynamically on the fly during training using Target Statistics.
   - Automatically computes pairwise and triplet feature combinations (e.g., User_ID x Ad_Category)
     without manual combinatorial feature engineering.


17.7 STACKING (STACKED GENERALIZATION) & VOTING CLASSIFIERS
--------------------------------------------------------------------------------
VOTING CLASSIFIERS:
- Hard Voting: Predicts the class label that received the majority of votes across models.
      Prediction = Mode( Model_1(x), Model_2(x), ..., Model_K(x) )
- Soft Voting: Averages predicted class probabilities and selects the argmax.
      Prediction = argmax_c [ (1 / K) * sum_{k=1}^{K} P_k(y = c | x) ]
  * Soft voting consistently outperforms hard voting because it weights high-confidence votes higher.

STACKING (STACKED GENERALIZATION):
- Architecture:
    * Level-0 Base Learners: Diverse algorithms with different inductive biases
      (e.g., Logistic Regression, Random Forest, XGBoost, CatBoost, KNN).
    * Level-1 Meta-Learner: A simple regularized linear model (e.g., LogisticRegression,
      RidgeClassifier) that learns how to optimally combine Level-0 predictions.
- Preventing Data Leakage via Out-Of-Fold (OOF) Training:
    * Base models CANNOT generate meta-features by predicting on their own training data
      (meta-learner would simply over-weight whichever model overfits most).
    * Solution: K-Fold Out-Of-Fold CV. Base models are trained on K-1 folds and predict on the
      held-out fold. These held-out predictions form the training matrix for the Meta-Learner.

18. ADVANCED FEATURE ENGINEERING & TARGET ENCODING
================================================================================

18.1 TARGET (MEAN) ENCODING: PRINCIPLES & TARGET LEAKAGE DANGER
--------------------------------------------------------------------------------
When categorical variables exhibit high cardinality (e.g., Postal Code with 10,000 unique values),
One-Hot Encoding leads to the curse of dimensionality, and Ordinal Encoding imposes arbitrary ordering.

Target (Mean) Encoding replaces each category label with the conditional expectation
of the target variable given that category:

    Encoded Value = Mean( y | Category = c ) = ( Sum of y for category c ) / ( Count of category c )

THE SEVERE TARGET LEAKAGE PITFALL:
- Consider a rare category appearing only ONCE in the dataset, with target y = 1.
- Its target encoding value becomes 1.0!
- The model immediately learns: "If feature == 1.0, predict y = 1 with 100% confidence."
- On validation or test data, this rare category fails completely, causing severe OVERFITTING.


18.2 M-ESTIMATE SMOOTHING FORMULA & OUT-OF-FOLD (OOF) TARGET ENCODING
--------------------------------------------------------------------------------
To prevent target leakage and regularize rare categories, two mandatory techniques are applied:

1. THE M-ESTIMATE SMOOTHING FORMULA:
   Blends the category-specific mean with the global target prior mean:

       y_smooth = [ n * mean_category + m * mean_global ] / [ n + m ]

   Where:
       n             = Total number of observations with category c.
       mean_category = Empirical mean of target y for category c in training data.
       mean_global   = Overall mean of target y across ALL training observations.
       m             = Smoothing parameter (weight assigned to the global prior).

   Behavior:
       * When n is very large (common category): n >> m, so y_smooth ≈ mean_category.
       * When n is very small (rare category):   n << m, so y_smooth ≈ mean_global.

2. OUT-OF-FOLD (OOF) TARGET ENCODING:
   Never encode a sample using target values that include that sample itself!
   - Partition the training data into K folds (e.g., K = 5).
   - For fold k, calculate the target encoding statistics using ONLY the data in the other K-1 folds.
   - For unseen test data, apply the final smoothed global encoding computed from the full training set.


18.3 POWER TRANSFORMATIONS: BOX-COX & YEO-JOHNSON
--------------------------------------------------------------------------------
Many parametric ML models (Linear/Logistic Regression, Neural Networks, PCA, LDA) assume
that features are approximately normally distributed with constant variance (homoscedasticity).
Power transformations apply a mathematical function to map skewed, non-normal distributions
into Gaussian-like, symmetric distributions.

1. BOX-COX TRANSFORMATION:
   - Constraint: Input x MUST be strictly positive (x > 0).
   - Formula:
         y(lambda) = [ x^lambda - 1 ] / lambda     (if lambda != 0)
         y(lambda) = ln(x)                         (if lambda == 0)
   - The parameter lambda is estimated via Maximum Likelihood Estimation (MLE).

2. YEO-JOHNSON TRANSFORMATION:
   - Advantage: Extends Box-Cox to handle ZERO and NEGATIVE numbers (all real numbers).
   - Formula:
         For x >= 0:
             y(lambda) = [ (x + 1)^lambda - 1 ] / lambda     (if lambda != 0)
             y(lambda) = ln(x + 1)                           (if lambda == 0)
         For x < 0:
             y(lambda) = - [ (-x + 1)^(2 - lambda) - 1 ] / (2 - lambda)  (if lambda != 2)
             y(lambda) = - ln(-x + 1)                                    (if lambda == 2)


18.4 QUANTILE & UNIFORM DISCRETIZATION (KBINSDISCRETIZER)
--------------------------------------------------------------------------------
Discretization (binning) converts continuous numerical features into discrete ordinal bins.
This introduces non-linear feature representations to linear models and reduces the impact
of extreme outliers.

Three Core Discretization Strategies (`KBinsDiscretizer`):
1. 'uniform':
   - All bins have identical width: Bin_Width = (x_max - x_min) / n_bins.
   - Weakness: Vulnerable to outliers; dense clusters get compressed into a single bin.
2. 'quantile':
   - All bins contain approximately the same number of samples (equal frequency).
   - Advantage: Highly robust to outliers; spreads data evenly across bins.
3. 'kmeans':
   - Bin boundaries are set by 1-D K-Means cluster centers.

19. MODERN HYPERPARAMETER OPTIMIZATION: OPTUNA & BAYESIAN OPTIMIZATION
================================================================================

19.1 LIMITATIONS OF GRID SEARCH & RANDOM SEARCH
--------------------------------------------------------------------------------
1. Grid Search:
   - Evaluates the exhaustive Cartesian product of specified hyperparameter values.
   - Complexity: Exponential growth O(k^d), where d is the number of parameters.
   - Flaw: Suffers severely from the Curse of Dimensionality; wastes vast compute
     evaluating unimportant hyperparameter dimensions.

2. Random Search:
   - Samples combinations uniformly at random from specified distributions.
   - Advantage: Discovers good parameters much faster than Grid Search in high-dimensional spaces.
   - Flaw: Completely MEMORYLESS. Each trial is independent; it never learns from
     past trial performance to focus search on promising regions.


19.2 SEQUENTIAL MODEL-BASED OPTIMIZATION (SMBO) & TPE
--------------------------------------------------------------------------------
Bayesian Optimization frames hyperparameter tuning as optimizing an expensive black-box
function f(theta). It constructs a probabilistic SURROGATE MODEL of the objective function
to intelligently guide the selection of the next set of hyperparameters.

TREE-STRUCTURED PARZEN ESTIMATORS (TPE):
Instead of directly modeling P(score | theta) with Gaussian Processes, TPE inverts the
probability using Bayes' rule: P(theta | score).

1. TPE divides past evaluated trials into two groups based on a score quantile threshold gamma:
       l(theta) = P(theta | score < y*)    --> Distribution of "good" hyperparameter values
       g(theta) = P(theta | score >= y*)   --> Distribution of "poor" hyperparameter values

2. Selection Criterion (Expected Improvement - EI):
       EI(theta) ∝ l(theta) / g(theta)

3. Optimization Strategy:
   To maximize Expected Improvement, TPE samples hyperparameter configurations where
   l(theta) is maximized (high probability of yielding top scores) and g(theta) is
   minimized (low probability of yielding poor scores).


19.3 AUTOMATED EARLY PRUNING (MEDIAN & SUCCESSIVE HALVING PRUNERS)
--------------------------------------------------------------------------------
In deep learning and large-scale gradient boosting, training an unpromising hyperparameter
configuration to completion wastes massive amounts of time and energy.

Automated Pruning (Asynchronous Early Stopping of Trials):
- Periodically checks the validation performance of a running trial at intermediate steps/epochs.
- Median Pruner: Compares the trial's score at step t against the median score of all previous
  completed trials at step t. If the current trial falls below the median, it is IMMEDIATELY KILLED.
- Result: Reduces total hyperparameter optimization compute time by 50% to 80%!


19.4 OPTUNA ARCHITECTURE: STUDIES, TRIALS, AND SEARCH SPACES
--------------------------------------------------------------------------------
Optuna is the modern standard Python framework for Bayesian Hyperparameter Optimization:

1. Study: The complete optimization session dedicated to a specific objective
   (e.g., `direction="maximize"` for AUC, `direction="minimize"` for LogLoss).
2. Trial: A single execution of the objective function evaluating one parameter candidate.
3. Dynamic Define-by-Run Search Space:
   - `trial.suggest_float("learning_rate", 1e-4, 1e-1, log=True)`: Log-uniform scale.
   - `trial.suggest_int("max_depth", 3, 12)`: Discrete integer range.
   - `trial.suggest_categorical("booster", ["gbtree", "dart"])`: Categorical selection.

21. MODEL INTERPRETABILITY & EXPLAINABILITY (XAI)
================================================================================

21.1 THE BLACK BOX PROBLEM: GLOBAL VS. LOCAL EXPLAINABILITY
--------------------------------------------------------------------------------
Complex machine learning models (Ensembles, Deep Neural Networks) are non-linear "black boxes".
Explainable AI (XAI) methods bridge the gap between predictive power and transparency.

- GLOBAL EXPLAINABILITY:
    * Seeks to answer: "How does the model make predictions in general across the entire dataset?"
    * Tools: Global Feature Importance, Partial Dependence Plots (PDP).
- LOCAL EXPLAINABILITY:
    * Seeks to answer: "Why did the model make THIS SPECIFIC prediction for THIS SPECIFIC individual?"
    * Tools: SHAP Waterfall Plots, LIME Local Surrogates.


21.2 IMPURITY IMPORTANCE (MDI) BIAS VS. PERMUTATION FEATURE IMPORTANCE
--------------------------------------------------------------------------------
1. MEAN DECREASE IN IMPURITY (MDI / GINI IMPORTANCE):
   - Mechanism: Sums the total impurity reduction (Gini/Variance) contributed by each feature
     across all tree splits. Built into `model.feature_importances_`.
   - CRITICAL FLAWS:
       * Severely biased toward continuous features and high-cardinality categorical features
         (because they present more split opportunities).
       * Computed on TRAINING data: a completely random noise feature can appear highly important
         simply because the tree overfitted on it!

2. PERMUTATION FEATURE IMPORTANCE:
   - Mechanism:
       a. Measure baseline metric (e.g., AUC or R2) on the held-out VALIDATION dataset.
       b. Randomly shuffle the values of a single feature column j, breaking its relationship with y.
       c. Pass the corrupted validation set through the model and recalculate the metric.
       d. Feature Importance = Baseline Metric - Corrupted Metric.
   - ADVANTAGES:
       * Model-agnostic (works on ANY model).
       * Evaluated on unseen validation data (unmasks overfitting).
       * Completely unbiased with respect to feature cardinality.


21.3 PARTIAL DEPENDENCE PLOTS (PDP) & INDIVIDUAL CONDITIONAL EXPECTATION (ICE)
--------------------------------------------------------------------------------
1. Partial Dependence Plot (PDP):
   - Shows the marginal effect of one or two features on the predicted target outcome,
     averaging over all other features.
   - Formula:
         f_s(x_s) = (1 / N) * sum_{i=1}^{N} f(x_s, x_{c,i})
   - Limitation: Averages out individual heterogeneity; can hide opposing subgroup interactions.

2. Individual Conditional Expectation (ICE):
   - Plots the functional relationship between feature x_s and the prediction for EACH individual
     instance separately (N distinct curves).
   - Advantage: Unmasks hidden interactions that cancel out in the average PDP line.


21.4 SHAP (SHAPLEY ADDITIVE EXPLANATIONS): GAME THEORY AXIOMS & VISUALIZATIONS
--------------------------------------------------------------------------------
Introduced by Lundberg and Lee (2017), SHAP grounds feature attribution in cooperative
game theory (Shapley Values, Nobel Prize in Economics).

CORE PREMISE:
- The prediction of an instance is viewed as a "payout" of a game.
- The features are "players" in a coalition collaborating to produce the payout.
- A feature's SHAP value (phi_i) is its marginal contribution across all possible coalitions.

THE FOUR MANDATORY MATHEMATICAL AXIOMS:
1. Efficiency:
   The sum of SHAP values across all features equals the difference between the model
   output f(x) and the expected baseline output E[f(x)]:
       sum_{i=1}^{M} phi_i = f(x) - E[f(x)]
2. Symmetry:
   If two features contribute identically to all possible feature subsets, their SHAP values are equal.
3. Dummy (Null Player):
   If a feature has zero impact on predictions across all possible coalitions, its SHAP value is 0.
4. Additivity:
   For an ensemble model (e.g., Random Forest), the SHAP value of a feature in the ensemble
   is the weighted average of its SHAP values in the individual trees.

POPULAR SHAP VISUALIZATIONS:
- Summary (Beeswarm) Plot: Global view showing feature impact magnitude and direction (positive/negative).
- Bar Plot: Mean absolute SHAP value (|phi_i|) representing global ranking.
- Waterfall Plot: Explains a single instance by showing how base value E[f(x)] is pushed up/down to f(x).
- Force Plot: Interactive visualization of positive (red) and negative (blue) forces driving prediction.


21.5 LIME (LOCAL INTERPRETABLE MODEL-AGNOSTIC EXPLANATIONS)
--------------------------------------------------------------------------------
Introduced by Ribeiro et al. (2016). While complex models are globally non-linear, they are
approximately LINEAR in the immediate local neighborhood around a single sample x.

LIME WORKFLOW:
1. Select the specific sample x to explain.
2. Perturb sample x to create synthetic neighboring samples.
3. Obtain black-box model predictions for all synthetic neighbors.
4. Weight each neighbor by its exponential distance to the original sample x:
       pi_x(z) = exp( - D(x, z)^2 / sigma^2 )
5. Train a simple, interpretable surrogate model (e.g., Ridge Regression or Decision Tree)
   on the weighted synthetic neighbors.
6. The coefficients of the local linear model serve as the local explanation.

22. SEMI-SUPERVISED LEARNING & SELF-TRAINING
================================================================================

22.1 THE SEMI-SUPERVISED SETTING: EXPLOITING UNLABELED DATA
--------------------------------------------------------------------------------
In many enterprise problems (fraud detection, medical diagnosis, document classification),
acquiring ground-truth labels is costly, labor-intensive, and slow, while unlabeled data is abundant.

Semi-Supervised Learning leverages a small labeled dataset L = {(x_i, y_i)} alongside a vast
unlabeled dataset U = {x_j} to build a superior classifier.

Underlying Assumptions:
1. Continuity Assumption: Points close in feature space likely share the same class label.
2. Cluster Assumption: Data naturally forms discrete clusters; the decision boundary passes
   through low-density regions.
3. Manifold Assumption: High-dimensional data lies approximately on a lower-dimensional manifold.


22.2 PSEUDO-LABELING VIA SELFTRAININGCLASSIFIER
--------------------------------------------------------------------------------
Self-Training (Pseudo-Labeling) is the most straightforward, model-agnostic semi-supervised technique:

ALGORITHMIC WORKFLOW:
1. Train a supervised base classifier (e.g., Logistic Regression, LightGBM, SVC) on labeled data L.
2. Pass the unlabeled dataset U through the trained model to predict class probabilities P(y | x).
3. Identify confident pseudo-labels: select samples where max(P(y | x)) >= threshold (e.g., 0.85).
4. Add these high-confidence pseudo-labeled samples into the labeled training set:
       L_new = L U { (x_k, y_pseudo_k) }
       U_new = U \ { x_k }
5. Re-train the base classifier on L_new.
6. Repeat steps 2-5 until no remaining unlabeled samples exceed the threshold or max_iter is reached.


22.3 GRAPH-BASED LABEL SPREADING & LABEL PROPAGATION
--------------------------------------------------------------------------------
1. Label Propagation:
   - Builds a fully connected similarity graph over all samples (labeled + unlabeled)
     using an RBF kernel: W_{ij} = exp(-gamma * ||x_i - x_j||^2).
   - Iteratively diffuses class labels along graph edges like heat transfer.
   - Clamps the originally labeled nodes to their true labels at every step.

2. Label Spreading:
   - Uses the normalized Graph Laplacian matrix for label diffusion.
   - Introduces a clamping/regularization factor alpha (0 < alpha < 1).
   - Advantage: Highly robust to label noise; allows original labels to adjust if contradicted
     by surrounding dense clusters.

23. COMPLETE MACHINE LEARNING ALGORITHM SELECTION MAP
================================================================================

23.2 ALGORITHM STRENGTHS, WEAKNESSES, AND ASSUMPTIONS CHEAT SHEET
--------------------------------------------------------------------------------
1. LINEAR / LOGISTIC REGRESSION:
   - Core Assumption: Linear relationship between features and target (or log-odds);
     independent observations; homoscedasticity; no severe multicollinearity.
   - Strengths: Highly interpretable, fast training/inference, low computational overhead.
   - Weaknesses: Cannot model non-linear interactions without manual feature engineering.
   - Scaling Needed? YES (standardize/normalize features).

2. DECISION TREES (CART):
   - Core Assumption: Non-parametric; no distributional assumptions.
   - Strengths: Completely interpretable, invariant to monotonic feature scaling, handles mixed types.
   - Weaknesses: Extremely high variance; prone to overfitting; unstable to small data perturbations.
   - Scaling Needed? NO.

3. RANDOM FOREST:
   - Core Assumption: Ensemble of decorrelated trees reduces variance.
   - Strengths: Robust to outliers and noise; resists overfitting; minimal hyperparameter tuning needed.
   - Weaknesses: Slower inference than linear models; cannot extrapolate beyond training range.
   - Scaling Needed? NO.

4. GRADIENT BOOSTED TREES (XGBoost / LightGBM / CatBoost):
   - Core Assumption: Sequential error correction yields superior non-linear boundaries.
   - Strengths: Unrivaled benchmark accuracy on tabular data; built-in regularization; handles missing data.
   - Weaknesses: Prone to overfitting without tuning; sensitive to noisy target labels.
   - Scaling Needed? NO.

5. SUPPORT VECTOR MACHINES (SVM):
   - Core Assumption: Classes are separable by hyperplanes (linear or mapped via kernel trick).
   - Strengths: Effective in high-dimensional spaces (P > N); robust against outliers via support vectors.
   - Weaknesses: O(N^2) to O(N^3) computational scaling (terrible on N > 50,000); requires scaling.
   - Scaling Needed? YES (strictly mandatory).

6. K-NEAREST NEIGHBORS (KNN):
   - Core Assumption: Points near each other in metric space share identical labels.
   - Strengths: Zero training time (lazy learner); simple concept; non-linear.
   - Weaknesses: O(N * P) inference latency; suffers severely from Curse of Dimensionality.
   - Scaling Needed? YES (strictly mandatory).

7. NAIVE BAYES:
   - Core Assumption: Features are conditionally independent given the class label.
   - Strengths: Blazing fast; performs exceptionally well on high-dimensional text classification.
   - Weaknesses: Independence assumption rarely holds in reality; yields poorly calibrated probabilities.
   - Scaling Needed? NO (for categorical / text counts).

24.1 MULTICOLLINEARITY & VARIANCE INFLATION FACTOR (VIF)
--------------------------------------------------------------------------------
Multicollinearity occurs when two or more independent predictor features are highly
linearly correlated with each other.

IMPACT ON MODELS:
- Tree-based models (Random Forest, XGBoost) are largely unaffected in predictive accuracy,
  but their feature importance scores become arbitrarily split between collinear features.
- Linear models (Linear/Logistic Regression) suffer SEVERELY:
    * Matrix (X^T * X) becomes close to singular (non-invertible).
    * Coefficient estimates become unstable with massive standard errors.
    * Signs of coefficients flip counter-intuitively (e.g., positive correlation shows negative sign).

VARIANCE INFLATION FACTOR (VIF):
Quantifies how much the variance of an estimated regression coefficient is inflated
due to collinearity with other features.

For feature j:
    VIF_j = 1 / ( 1 - R_j^2 )

Where R_j^2 is the R-squared obtained by regressing feature j against ALL other features.

Interpretation Rule of Thumb:
- VIF = 1.0:       Zero correlation with other features.
- 1.0 < VIF < 5.0: Moderate correlation (generally acceptable).
- VIF >= 5.0:      High collinearity (investigate and monitor).
- VIF >= 10.0:     Severe collinearity! Requires immediate mitigation (drop feature,
                   combine features, or apply Ridge regularization).


24.2 DATA DRIFT, CONCEPT DRIFT, COVARIATE SHIFT & DETECTION METHODS
--------------------------------------------------------------------------------
In real-world production systems, data distributions degrade over time.

1. COVARIATE SHIFT (Data Drift):
   - Definition: The input feature distribution P(X) changes over time, while the conditional
     probability of the target given the features P(y | X) remains CONSTANT.
   - Example: An e-commerce model trained on young shoppers (18-25) is now deployed to an
     older demographic (50-70), but the relationship between income and purchase remains unchanged.

2. CONCEPT DRIFT:
   - Definition: The fundamental statistical relationship between inputs and outputs P(y | X)
     CHANGES over time, regardless of whether P(X) changes.
   - Example: Fraudsters adopt completely new evasion patterns, so transactions with previously
     benign features are now fraudulent.

3. PRIOR PROBABILITY SHIFT:
   - Definition: The marginal distribution of the target P(y) changes over time.
   - Example: A pandemic hits, causing credit default base rate to spike from 2% to 15%.

DRIFT DETECTION METHODOLOGIES:
- Kolmogorov-Smirnov (KS) Test: Non-parametric 2-sample test comparing continuous feature distributions.
- Population Stability Index (PSI):
      PSI = sum [ (Actual% - Expected%) * ln(Actual% / Expected%) ]
      * PSI < 0.1: No significant drift.
      * 0.1 <= PSI <= 0.2: Moderate drift (monitor).
      * PSI > 0.2: Significant drift! Triggers automated model retraining.
- Adversarial Validation:
      Train a binary classifier to distinguish between training data (label 0) and current
      production data (label 1). If AUC >> 0.50 (e.g., AUC > 0.70), significant drift has occurred!


24.3 PROBABILITY CALIBRATION: PLATT SCALING VS. ISOTONIC REGRESSION
--------------------------------------------------------------------------------
A classification model is CALIBRATED if a predicted probability of p corresponds to an
empirical event occurrence rate of p (e.g., among all patients predicted to have disease with
probability 0.80, exactly 80% actually have the disease).

- Uncalibrated Algorithms:
    * Naive Bayes: Pushes probabilities toward 0 and 1 due to violated independence assumptions.
    * Support Vector Machines (SVM): Max-margin objective does not optimize probability distribution.
    * Boosted Decision Trees: Frequently pushes probabilities away from extremes toward the center.

EVALUATING CALIBRATION:
- Brier Score (Mean Squared Error in Probability Space):
      Brier Score = (1 / N) * sum_{i=1}^{N} ( p_i - y_i )^2
- Calibration Curve (Reliability Diagram):
      Plots predicted average probability bins on the x-axis vs. true empirical fraction of
      positive labels on the y-axis. A perfectly calibrated model forms a diagonal line y = x.

CALIBRATION TECHNIQUES (`CalibratedClassifierCV`):
1. Platt Scaling (`method='sigmoid'`):
   - Fits a univariate logistic regression model to the raw decision scores:
         P(y = 1 | f) = 1 / ( 1 + exp(A * f + B) )
   - Best when: Dataset is small, or distortion is monotonic and sigmoid-shaped.
2. Isotonic Regression (`method='isotonic'`):
   - Non-parametric piecewise constant step-function that enforces monotonicity:
         y_i <= y_j whenever f_i <= f_j
   - Best when: Sufficient calibration data is available (N > 1,000) and distortion is non-sigmoid.


24.4 TOP 10 CLASSICAL ML TECHNICAL INTERVIEW QUESTIONS & RIGOROUS ANSWERS
--------------------------------------------------------------------------------
Q1: Why is Mean Squared Error (MSE) not used as the loss function for Logistic Regression?
A1: If MSE (y - sigma(z))^2 is paired with the non-linear sigmoid activation function, the resulting
    loss surface with respect to weights w becomes NON-CONVEX. It creates multiple local minima and
    saddle points where gradients vanish, preventing gradient descent from converging to the global
    optimum. Binary Cross-Entropy (Log-Loss) guarantees a strictly CONVEX loss surface with a unique
    global minimum.

Q2: Why does L1 regularization (Lasso) produce sparse solutions (feature selection) while L2 (Ridge) does not?
A2: Lasso adds the sum of absolute values |w_j|, whose diamond-shaped constraint boundary in parameter
    space has sharp corners on the coordinate axes. The elliptical contours of the MSE loss function
    frequently intersect these constraint corners where one or more weights w_j are EXACTLY ZERO.
    Ridge adds the sum of squared weights w_j^2, producing a smooth spherical constraint boundary that
    shrinks weights asymptotically toward zero but almost never sets them exactly to zero.

Q3: What is the Curse of Dimensionality and how does it degrade distance-based algorithms?
A3: As the number of feature dimensions P increases, the volume of feature space grows exponentially,
    causing data points to become extremely sparse. In high-dimensional spaces, the Euclidean distance
    between the nearest neighbor and the furthest neighbor approaches zero relative to their average
    distance: (d_max - d_min) / d_min -> 0. Consequently, distance metrics lose discriminative power,
    causing algorithms like KNN, K-Means, and SVM to fail without dimensionality reduction.

Q4: What is the fundamental difference between Bagging and Boosting in terms of bias and variance?
A4: Bagging trains high-variance, deep base models independently on bootstrap samples and averages
    them. Averaging independent estimators reduces variance by a factor of 1/K without altering bias.
    Boosting trains low-capacity weak models sequentially, with each model targeting the residual errors
    of the ensemble. This additive functional gradient descent primarily reduces bias.

Q5: When should you evaluate a model using the Precision-Recall (PR) Curve instead of the ROC Curve?
A5: Under extreme class imbalance (e.g., fraud rate = 0.1%), the False Positive Rate (FPR) in ROC:
    FPR = FP / (FP + TN) remains deceivingly small because TN is enormous. As a result, ROC AUC can
    appear deceptively high (e.g., 0.98) even when the model generates hundreds of false alarms.
    The PR Curve plots Precision = TP / (TP + FP) vs. Recall = TP / (TP + FN). It does not include TN,
    making it acutely sensitive to false alarms in heavily imbalanced scenarios.

Q6: What is Data Leakage, and what is the single most common cause in ML pipelines?
A6: Data Leakage occurs when information from outside the training dataset (specifically target or
    test set distributions) is inadvertently introduced into the model during training.
    The most common cause is performing global preprocessing (e.g., imputing missing values with the
    global mean, scaling features with global min/max, or computing target encodings) across the ENTIRE
    dataset BEFORE splitting into train and test sets.
    Fix: Fit all transformers strictly on the training partition and use `Pipeline` objects.

Q7: Explain the mechanism of Early Stopping and why it acts as a regularizer.
A7: Early Stopping monitors validation loss at the end of every training epoch/iteration. If validation
    loss fails to improve for a pre-specified number of rounds (patience), training is halted and the
    weights corresponding to the best validation checkpoint are restored. It acts as an implicit
    regularizer by restricting the volume of parameter space the optimization algorithm can explore,
    preventing the model from adapting to training noise.

Q8: How does XGBoost handle missing values during training and inference?
A8: XGBoost implements Sparsity-Aware Split Finding. During node splitting, instances with missing
    values are first routed exclusively to the left child, and the split gain is calculated. Then they
    are routed to the right child, and gain is recalculated. XGBoost selects whichever direction
    produces the maximum split gain as the default branch for missing values. During inference, any
    test sample with a missing value is automatically routed down that learned default branch.

Q9: What is the difference between Transductive and Inductive Learning?
A9: Inductive Learning learns a general mapping function f(x) from training data that can be applied to
    unseen test points at any future time (e.g., Random Forest, Logistic Regression).
    Transductive Learning aims to predict labels ONLY for a specific, pre-existing set of unlabeled
    points observed during training (e.g., Label Propagation, Graph Transduction). It cannot generalize
    to novel unseen points without re-running the entire graph diffusion algorithm.

Q10: Why does CatBoost utilize Symmetric (Oblivious) Trees instead of standard asymmetric trees?
A10: Symmetric trees enforce the identical split condition across all nodes at the same tree depth.
     This architectural constraint provides two massive advantages:
     1. Structural Regularization: Dramatically limits tree complexity and protects against overfitting.
     2. Blazing CPU Inference Speed: The tree evaluation can be compiled into simple SIMD bitwise masks,
        executing up to an order of magnitude faster than evaluating nested if-else branching logic.
