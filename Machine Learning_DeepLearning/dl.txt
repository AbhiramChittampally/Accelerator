Part 9 — Feature extraction vs fine-tuning
Property	Feature extraction	Fine-tuning
Pretrained backbone	Frozen	Some or all layers train
New classification head	Trained	Trained
Data requirement	Often works well with smaller datasets	Usually benefits from more labeled data
Training speed	Faster	Slower
Overfitting risk	Generally lower on small datasets	Generally higher on small datasets
Best starting point	Similar source and target tasks	More adaptation needed









Part 10 — How do you choose?
Case A
Small dataset + similar task
Start with feature extraction. Freeze the pretrained backbone and train the new head.


Case B
Moderate dataset + some task differences
Consider partial fine-tuning: freeze early layers and train later layers plus the head.


Case C
Large dataset + substantial task differences
Consider fine-tuning more of the model, potentially the full backbone, while monitoring validation performance.











Transfer learning = reuse pretrained knowledge for a target task.
Two strategies
- Feature extraction: freeze backbone; train the new head.
- Fine-tuning: unfreeze some or all pretrained layers and train them further.

Avoid full fine-tuning by default when:
- The target dataset is very small.
- Validation performance indicates overfitting.
- Compute or GPU memory is insufficient.
- The pretrained model's domain is poorly matched to the target task.
Monitor overfitting
- Training loss decreases while validation loss rises: possible overfitting.
- Save the best validation checkpoint.
- Try freezing more layers or reducing the learning rate.
Small dataset improvements
- Feature extraction.
- Appropriate data augmentation.
- Partial fine-tuning if needed.
- A pretrained model from a closer domain.
Always check
- Expected image preprocessing.
- Number of examples per class.
- Validation results.
- Model and dataset licenses.







Definition
Model serving makes a trained model available to applications so they can send input and receive predictions reliably.
The essential pipeline
Train → Save checkpoint → Load model → Validate input → Inference → Return prediction
Key differences
- Training updates weights.
- Inference generates predictions without updating weights.
- Serving provides the surrounding system through which inference is accessed.
PyTorch inference pattern
model.load_state_dict(state_dict)model.eval()with torch.no_grad():    prediction = model(input_tensor)



Three serving patterns
- Online: individual, latency-sensitive requests.
- Batch: many records processed together.
- On-device: model runs on the user's device.
Important terms
- Checkpoint: saved model parameters and possibly training state.
- Endpoint: an interface for requesting predictions.
- Latency: time to return a response.
- Throughput: number of requests or records processed per unit time.
- Scalability: ability to handle changing workload.
Remember: serving doesn't normally retrain the model. It uses the learned parameters to produce predictions.
